# Maintainer guide

Behavior flows from raw Malbolge through MBP1 to ahead-of-time generated JVM bytecode. Never add a feature handler, dispatch table, or JSON-printing feature unit.

Keep the generic ABI small. Put behavior/constants in Malbolge; put only reusable Android, DexKit, networking, storage, UI, and libxposed mechanisms in conventional code. Runtime resolution is cached, bounded, uniqueness-checked, and fail-open. `target/current` is fallback/regression evidence only.

Run `python toolchain/check_purity.py`, Python tests, debug/release builds, and inspect generated bytecode before release.
