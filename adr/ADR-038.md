# ADR-038 — SponsorBlock segment requests are an opt-in feature network path

**Status:** Accepted for development; release gated

## Decision

The SponsorBlock Feature may issue one HTTPS GET per newly observed video to the
`api_origin` declared by its Malbolge `SegmentSource` record
(`https://sponsor.ajay.app`). The request uses the privacy-preserving hash-prefix route
`/api/skipSegments/{first 4 hex chars of SHA-256(videoId)}`, so the full video ID is not
sent. It carries no account, cookie, token, or module-generated identifier.

The request runs on a short-lived daemon thread started from the WARM `video_stage`
Endpoint. The HOT `playback_progress` callback performs no network, disk, Binder,
reflection lookup, logging, or allocation; it reads one immutable segment table and, at
most once per segment, calls the pre-bound seek member.

Segments are data, never executable payload. Only `actionType=skip` segments of
categories declared by the `SegmentSource` are kept, and each is gated at skip time by
its own RemotePreferences `ConfigItem`.

## Reason

SponsorBlock has no offline source of segment data. The architecture baseline
(`contracts/security-privacy.md`) forbids network I/O required by the architecture and
network I/O in HOT callbacks (INV-030); it does not forbid an opt-in feature request
made off the HOT path.

## Consequence

- Disabling `sponsorblock_enabled` stops video observation, requests, and skipping.
- Diagnostics log only segment counts and skip events, never the video ID.
- Response bodies are capped at 1 MiB; failures leave the table empty (original
  playback).
- Voting, submission, manual skip buttons, seekbar markers, and the channel whitelist
  from Morphe are not ported.
