# ADR-039 — Settings entry in YouTube, edits in the generated manager

**Status:** Accepted for development; release gated

## Decision

The module's settings surface has two parts, both compiled from the Malbolge
`SettingsPage` record in `source/40_manager/manager_settings.mal`:

1. **Entry section (YouTube process, read-only).** After YouTube's root settings screen
   builder (`own.run()`) clears and rebuilds the `PreferenceScreen`, the generated
   `SettingsEntry` adds one `PreferenceCategory` ordered above YouTube's first category
   (Account), with one row per page section. Rows use YouTube's own
   `preference_group_title` / `preference_with_icon` layouts and themed icons, and carry
   an explicit Intent to the module's manager Activity. The entry holds no state and
   writes nothing.
2. **Manager Activity (module process).** `ManagerActivity` shows one switch per
   `ConfigItem` and commits changes through libxposed service 102
   (`XposedService.getRemotePreferences(group).edit().commit()`), keeping one
   process-lifetime `XposedService` in `ManagerService`.

## Reason

Vector's injected-process RemotePreferences view is read-only, and
`contracts/configuration.md` makes RemotePreferences the only persistent store, written
only from the manager. Launching the manager keeps a single write path with no broadcast
or custom IPC, while the entry makes the settings discoverable where users expect them.

## Consequence

- Every `ConfigItem` must appear exactly once in the `SettingsPage` (validator gate).
- The entry Effect is the only unguarded Effect: it cannot be switched off from itself.
- YouTube's running process picks up changes through its existing preference listener.
- Any failure while building the entry is logged and leaves YouTube's screen unchanged.
